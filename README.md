# Helpdesk

Простая веб-система для создания и обработки заявок в службу поддержки. Проект реализован на Java с использованием стандартной библиотеки, без базы данных и сторонних Java-библиотек.

## Возможности

- Создание заявки с указанием имени автора, темы и описания проблемы.
- Просмотр списка заявок.
- Фильтрация заявок по статусу.
- Изменение статуса заявки.
- Автоматическое присвоение номера и даты создания.
- Сохранение заявок в текстовый файл и загрузка данных при следующем запуске.
- Отображение ошибок при некорректном заполнении формы.
- Защита от выполнения HTML-разметки, введённой в текст заявки.
- Адаптивный веб-интерфейс на русском языке.

### Статусы заявок

| Код | Отображение | Описание |
|---|---|---|
| `NEW` | Новая | Статус при создании заявки |
| `IN_PROGRESS` | В работе | Заявка обрабатывается |
| `DONE` | Готово | Работа по заявке завершена |

## Технологии

- **Java 11 или новее** — серверная часть.
- **Java HttpServer** — встроенный HTTP-сервер из стандартной библиотеки Java.
- **HTML, CSS, JavaScript** — веб-интерфейс.
- **HTTP и JSON** — обмен данными между браузером и сервером.
- **Текстовый файл `tickets.txt`** — хранение заявок.
- **Docker** — запуск приложения в контейнере.
- **Автотесты на Java** — проверка логики хранения заявок.

Проект не использует Spring Boot, Maven, Node.js, npm или внешние библиотеки. Компиляция выполняется командой `javac`.

## Требования

Для локального запуска требуется JDK 11 или новее. Рекомендуется JDK 17, который используется в Dockerfile.

## Запуск проекта

Перед запуском перейдите в корневую папку проекта — `helpdesk`.

### Linux / macOS

```bash
chmod +x run.sh run-tests.sh
./run.sh
```

### Windows

```bat
run.bat
```

Скрипт компилирует исходные файлы из `src/` в каталог `out/` и запускает сервер.

После запуска откройте в браузере:

**http://localhost:8080**

Остановить сервер можно сочетанием `Ctrl+C` в терминале.

## Запуск через Docker

Убедитесь, что Docker установлен и запущен. Выполните команды из корневой папки проекта:

```bash
mvn clean package
docker build -t helpdesk .
docker run --rm -p 8080:8080 helpdesk
```

После запуска приложение будет доступно по адресу http://localhost:8080.

### Сохранение данных при использовании Docker

По умолчанию файл заявок создаётся внутри контейнера. Чтобы хранить данные на компьютере и сохранять их между пересозданиями контейнера, можно подключить каталог или файл через переменную `DATA_FILE`.

Например, предварительно создайте каталог `data`, затем запустите:

```bash
docker run --rm -p 8080:8080 \
  -e DATA_FILE=/data/tickets.txt \
  -v "$(pwd)/data:/data" \
  helpdesk
```

Для Windows PowerShell синтаксис пути в `-v` может отличаться в зависимости от расположения проекта и версии Docker.

## Настройки

Приложение поддерживает следующие переменные окружения:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт HTTP-сервера |
| `DATA_FILE` | `tickets.txt` | Путь к файлу хранения заявок |

```bash
PORT=8081 ./run.sh
```

После этого приложение будет доступно по адресу http://localhost:8081.

## API

Базовый путь API: `/api/tickets`. Запросы создания и изменения данных принимают поля формы (`application/x-www-form-urlencoded`), а ответы возвращаются в формате JSON с кодировкой UTF-8.

### Получить список заявок

```http
GET /api/tickets
```

Возвращает массив заявок.

Пример ответа:

```json
[
  {
    "id": 1,
    "title": "Не работает принтер",
    "description": "Принтер не печатает документы",
    "author": "Анна",
    "status": "NEW",
    "createdAt": "2026-10-15 12:30"
  }
]
```

### Создать заявку

```http
POST /api/tickets
Content-Type: application/x-www-form-urlencoded
```

Поля запроса:

| Поле | Обязательное | Описание |
|---|---|---|
| `author` | Да | Имя автора заявки |
| `title` | Да | Тема заявки |
| `description` | Нет | Описание проблемы |

Пример с `curl`:

```bash
curl -X POST http://localhost:8080/api/tickets \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "author=Анна" \
  --data-urlencode "title=Не работает принтер" \
  --data-urlencode "description=Принтер не печатает документы"
```

При успешном создании сервер возвращает `201 Created` и объект заявки. Новый тикет получает уникальный в пределах файла числовой `id`, статус `NEW` и дату создания.

Если имя или тема не указаны, сервер возвращает `400 Bad Request` с сообщением:

```json
{"error":"Укажите имя и тему заявки"}
```

### Изменить статус заявки

```http
POST /api/tickets/{id}/status
Content-Type: application/x-www-form-urlencoded
```

Допустимые значения поля `status`: `NEW`, `IN_PROGRESS`, `DONE`.

Пример:

```bash
curl -X POST http://localhost:8080/api/tickets/1/status \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "status=IN_PROGRESS"
```

При успешном изменении возвращается `200 OK`:

```json
{"ok":true}
```

Если заявка не найдена или указан недопустимый статус, возвращается `404 Not Found`:

```json
{"error":"Заявка или статус не найдены"}
```

> В текущей реализации сервер проверяет допустимость значения статуса, но не ограничивает последовательность переходов между статусами.

### Коды ответов

| Код | Значение |
|---|---|
| `200` | Успешное чтение или изменение |
| `201` | Заявка успешно создана |
| `400` | Не указаны обязательные поля при создании |
| `404` | Маршрут, заявка или статус не найдены |
| `500` | Внутренняя ошибка сервера |

## Модель заявки

Объект `Ticket` содержит следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `id` | `int` | Номер заявки |
| `title` | `String` | Тема |
| `description` | `String` | Описание проблемы |
| `author` | `String` | Имя автора |
| `status` | `String` | Статус заявки |
| `createdAt` | `String` | Дата и время создания |

## Хранение данных

Заявки хранятся в текстовом файле `tickets.txt`. По умолчанию файл создаётся в рабочем каталоге приложения. При старте сервер загружает из него ранее сохранённые заявки, а при создании заявки или изменении статуса записывает данные в файл.

Формат хранения — одна заявка на строку, поля разделены табуляцией. Специальные символы в текстовых полях экранируются, поэтому кириллица, переносы строк и табуляции могут сохраняться.

База данных не используется.

## Тестирование

Автотесты проверяют:
- пустое хранилище при первом запуске;
- создание заявки и начальный статус `NEW`;
- смену статуса;
- отклонение недопустимого статуса и несуществующего номера;
- сохранение и повторную загрузку данных;
- сохранение кириллицы, табуляций и переносов строк;
- продолжение нумерации после перезапуска хранилища.

### Linux / macOS

```bash
./run-tests.sh
```

### Windows

```bat
run-tests.bat
```

Тесты используют `javac` и запускаются без JUnit или других внешних библиотек. При успешном прохождении в консоли выводится количество пройденных и проваленных проверок.

## Ограничения текущей версии

- Авторизация и разграничение прав пользователей не реализованы.
- Комментарии, назначение исполнителя и email-уведомления не реализованы.
- В заявке используется имя автора, а не отдельные поля имени и email клиента.
- Хранение организовано в текстовом файле, без базы данных.
- API поддерживает только получение списка, создание заявки и изменение статуса.
- Переходы статусов не ограничены бизнес-правилами, кроме проверки допустимого значения.
- Формат запросов на создание и изменение статуса — URL-encoded форма, а не JSON.
- Сборка выполняется напрямую через `javac`, без Maven или Gradle.
