# Техническое задание: простой Helpdesk

## 1. Общие сведения

| Пункт | Описание |
|---|---|
| Название | Helpdesk (система приёма заявок) |
| Язык | Java 11 и выше |
| Тип | Веб-приложение (сервер на Java + страница в браузере) |
| Внешние библиотеки | Не используются (только стандартная библиотека Java) |
| База данных | Не используется, заявки хранятся в текстовом файле `tickets.txt` |

## 2. Цель проекта

Сделать максимально простую и понятную систему, где пользователь может отправить заявку
о проблеме, а сотрудник поддержки может видеть все заявки и менять их статус.

## 3. Команда и зоны ответственности

| Роль | Что делает | Файлы |
|---|---|---|
| Дизайнер | Внешний вид: цвета, шрифты, карточки, кнопки, статусы | `web/style.css` |
| Frontend | Страница в браузере: форма, список, фильтры, запросы к серверу | `web/index.html`, `web/app.js` |
| Backend | Сервер, API, хранение заявок в файле | `src/Main.java`, `src/Ticket.java`, `src/TicketStore.java` |
| DevOps | Сборка, запуск, контейнер | `run.sh`, `run.bat`, `Dockerfile` |
| Тестировщик | Автотесты и ручное тестирование | `test/TicketStoreTest.java`, `run-tests.sh`, раздел 8 |

## 4. Функциональные требования

### 4.1. Заявка
Поля заявки: номер (id), тема, описание, имя автора, статус, дата создания.

### 4.2. Статусы
- `NEW` (Новая): ставится автоматически при создании
- `IN_PROGRESS` (В работе)
- `DONE` (Готово)

### 4.3. Что умеет система

| № | Требование |
|---|---|
| F1 | Создать заявку (обязательно имя и тема, описание по желанию) |
| F2 | Показать список всех заявок, новые сверху |
| F3 | Сменить статус заявки |
| F4 | Фильтровать список по статусу (Все / Новые / В работе / Готово) |
| F5 | Сохранять заявки в файл и загружать их при запуске сервера |
| F6 | Показывать понятное сообщение об ошибке, если форма заполнена неверно |

## 5. API (backend)

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/tickets` | Список заявок (JSON) |
| POST | `/api/tickets` | Создать заявку (`author`, `title`, `description`) |
| POST | `/api/tickets/{id}/status` | Сменить статус (`status`) |

Коды ответов: `200` и `201` успех, `400` неверные данные, `404` не найдено, `500` ошибка сервера.

## 6. Нефункциональные требования

- Запуск одной командой (`run.sh` или `run.bat`).
- Адаптивная страница (нормально выглядит на телефоне и компьютере).
- Защита от внедрения HTML-кода в тексте заявок.
- Защита от выхода за пределы папки `web` при отдаче файлов.
- Код с понятными комментариями на русском языке.

## 7. Что НЕ входит в проект (чтобы было просто)

Авторизация и роли, база данных, отправка email, вложения, комментарии к заявкам.
Это можно добавить на следующих этапах.

## 8. Тестирование

### 8.1. Автотесты
`TicketStoreTest` проверяет: создание заявки, статус по умолчанию, смену статуса,
отклонение неверных данных, сохранение в файл, кириллицу, переносы строк.

### 8.2. Ручные тесты

| № | Действие | Ожидаемый результат |
|---|---|---|
| T1 | Отправить форму с пустыми полями | Сообщение «Укажите имя и тему заявки» |
| T2 | Создать заявку | Заявка появилась вверху списка со статусом «Новая» |
| T3 | Сменить статус на «Готово» | Цвет полоски стал зелёным, после обновления страницы статус сохранился |
| T4 | Нажать фильтр «В работе» | Показаны только заявки в работе |
| T5 | Перезапустить сервер | Все заявки на месте |
| T6 | Ввести в теме `<b>тест</b>` | Текст показан как есть, без жирного шрифта |

## 9. Этапы работы

1. Дизайнер и Frontend договариваются о внешнем виде страницы.
2. Backend делает API и хранение заявок.
3. Frontend подключает страницу к API.
4. Тестировщик пишет и запускает тесты.
5. DevOps готовит запуск и Dockerfile.
6. Общая проверка по разделу 8.

## 10. Критерии приёмки

Проект принят, если выполнены все требования F1-F6, проходят все автотесты и ручные тесты T1-T6.
